# The theory of rdra-ish's verification

This directory states what rdra-ish's verification tools decide, under which assumptions,
and on what evidence, for a reader trained in formal methods. Each document defines its
terms before it uses them, states its guarantees as propositions, and says for each one
whether it rests on a proof, a mechanical check, a differential test, or an assumption.

The documents describe the code at commit `b83b9544ccdef3701bf90383cd56d10ea2297787`
(origin/main, 2026-11-28). They cite code by symbol (`crate/src/path.rs::function`), never by
line. A document that is brought up to date with a later commit says so in its first
paragraph.

## Reading order

1. [semantics.md](./semantics.md), whole. Everything else is stated in its notation.
2. [claims.md](./claims.md), to see what is claimed and how well each claim is supported.
3. (c), then (a). The native verifier decides a check on one explored graph; the cone
   document says why a graph of a cone, a reduced cone, or a quotient by symmetry decides
   what the model's graph would.
4. (b), which is independent of (a) and (c) except for the interaction with BFS
   refutation and bound escalation.
5. (d), last, since it is the evidence for claims the others make.

## Open problems

Each item is a stated guarantee the code does not give, a disagreement between documents
that bears on what a verdict means, or a gap in the evidence for a claim. Nothing here has
been weakened in the code or the notes; the owner decides which become issues. The
[claims inventory](./claims.md) refers to these by number.

Kinds: **guarantee** (a verdict can mean less than the tools or notes say), **evidence** (the
claim may hold, but its evidence is weaker than stated), **prose** (a note or code comment
disagrees with the code, with no effect on a verdict). Two items show a wrong `ok` of
`T_β(M)`, both reproduced: P54, at one instance, where a value past a byte wraps when the
build encodes it (a nullable Int column at `m = 255`, or a nullable Enum of 256 values), and
P50, at bounds no sample uses, where the packing of a state past 65,535 bits merges states
([native.md](./native.md#the-state-store-and-its-encoding)). P40 is the nullable-Int case of
P54, found independently for z3: it shows an `ok` and a `proved` that are wrong with respect
to the model text, because at `--int-range-max 255` the build itself misreads it. P55 is a
third fixed-width fault of the same family, read only. P43 shows a `proved` whose printed
reach ("any Int value") is wrong, because a larger `--int-range-max` gives a counterexample.
P32 shows that an entity cone can fail to report a deadlock, a state with no witness, or a use
case that never runs. P30 could give a wrong verdict if a model reached it. P51 and P56 are of
another sort: both engines agree, but the `ok` they print is not one that D17 or D20 of
[semantics.md](./semantics.md), as written, licenses. P1, P3, P4, P20, P30, P32, P40, P43, P50,
P51, P54, P55, and P56 are the items that bear on what a printed verdict means. This list is
what has been found, not a bound on what exists.

Numbering: P1 to P21 come from the survey for the claims inventory. Each theme document numbers
its items in a block of its own: theme (a) ([cones.md](./cones.md)) from P30, theme (b)
([z3.md](./z3.md)) from P40, theme (c) ([native.md](./native.md)) from P50, and theme (d)
([tlc-agreement.md](./tlc-agreement.md)) from P22 to P29, of which it uses P22 to P24. Each
theme's items stay in one block.

Status: **read** means the code was read for this document and shows the problem;
**reported** means a reading of the code during the survey for the claims inventory found it
and this document did not re-read it. **reproduced** means a run of the tools shows it;
the model and output are in the theme document named in the row. P4 (scope part), P40, P41,
and P43 were reproduced for [z3.md](./z3.md#reproductions), P50 and P51 for
[native.md](./native.md#reproductions), and P54 by the review of native.md (recorded there);
every other item is a reading of the code at the pinned commit, and the issue that takes it up
should start with a reproduction.
